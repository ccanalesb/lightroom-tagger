Bring your own provider

The question this demo exists to answer: what is the smallest set of things a photographer has to type in for any HTTP-reachable, OpenAI-compatible model server — Ollama, LM Studio, vLLM, llama.cpp, OpenRouter, Groq, a company proxy — to actually produce a description of a photo? And where does the API key live once they have typed it?

Today providers.json is hand-edited and understands three providers. Below you can add any provider you like, probe it, discover its models, and watch the one thing that matters: whether a describe job would succeed right now. Nothing here talks to the real network — the servers are simulated, including which ones are switched on.

    Proposed providers.json shape

    Two collapses versus today: base_url / base_url_env / base_url_default become one { from, value } pair, and api_key / api_key_env become one auth block that can also say "this endpoint needs no credential" — which is what the literal "api_key": "ollama" in today's file is faking. native_chat and auto_discover are gone: discovery is a button, not a flag.

    
    
    
  
    

  
    What the demo is built to expose
    
  
    
    
    A models list is not proof it works. The current health check calls
    GET /models and shows a green tick. Walkthrough 4 adds an endpoint that answers
    /models perfectly and then cannot chat at all. Reachable and usable are two different
    questions and need two different probes.
    
    
    
    
    Nothing tells you which models can see. OpenAI's /models
    returns bare ids with no capability information, so every discovered model arrives as
    vision: unknown. Today the code sidesteps this by marking every Ollama model
    vision-capable, which is wrong for llama3.1:8b. Here a one-pixel image probe settles it
    per model, and until it runs, a describe job has nothing it can honestly pick.
    
    
    
    
    Someone has to decide where a typed key goes. An environment variable
    reference keeps secrets off disk but means the user must also edit their shell — which defeats the
    point of a UI. Storing it inline puts a plaintext key in providers.json. Walkthrough 3
    makes both consequences visible; the demo does not pick for you.
